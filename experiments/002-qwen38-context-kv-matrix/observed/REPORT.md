# 観測記録

## 成功ケース

| 入力 | 生成 | KV配置 | 計測時間(s) | total tok/s |
|---:|---:|---|---:|---:|
| 128 | 64 | GPU F16 | 15.727 | 12.209 |
| 128 | 256 | GPU F16 | 56.438 | 6.804 |
| 128 | 1024 | GPU F16 | 302.143 | 3.813 |
| 2048 | 64 | GPU F16 | 91.638 | 23.047 |
| 2048 | 256 | GPU F16 | 151.466 | 15.211 |
| 2048 | 1024 | GPU F16 | 395.216 | 7.773 |
| 8192 | 64 | CPU F16 | 390.499 | 21.142 |
| 8192 | 256 | CPU F16 | 440.925 | 19.160 |
| 8192 | 1024 | CPU F16 | 894.961 | 10.298 |

`total tok/s`は入力処理と生成の合算値であり、generation tok/sではない。

## 失敗境界

- 8192+64、GPU F16 KV: 最大RSS 18.361GB、prompt warmupで確保失敗。
- 8192+64、GPU F16 KV、ubatch 32: 最大RSS 18.653GB、確保失敗。
- 8192+64、GPU Q8 KV、ubatch 8: 最大RSS 18.131GB、確保失敗。
- 8192+64、CPU F16 KV、ubatch 32: 最大RSS 18.421GB、成功。

全実行で対象プロセスのswapは0だった。60層Metal＋6層CPUへの部分オフロードはRSSが19.540GBまで増え、改善にならなかった。

## 解釈

8KではKVをCPUに置くことで動作境界を越えられるが、長い入力と生成は大幅に遅くなる。GPU KVの量子化だけでは、この24GB M3環境の8192入力境界を越えられなかった。
